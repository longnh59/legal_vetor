§  SYS T E M  O V E RV I E W
Five stages, one report
A lawyer submits a draft provision (or a whole draft document). The system
decomposes it into clause-level queries and, for each clause, produces a cited
compatibility report: which existing Đ i ề u/Kho ả n are relevant, whether each is
conflicting, overlapping, or compatible, and how severe the finding is given the
legal hierarchy. RAG is the backbone of one stage out of five.

01 Decompose & filter
Split the draft into its own Đ i ề u/Kho ả n; derive structured filters (sector, hierarchy
level of the proposed document, validity = current only).
02 Hybrid retrieval
BM25 + dense embeddings (bge-m3) over article-level chunks, metadata-
filtered, then cross-encoder reranking to top ~10 per clause.
03 Graph expansion
For each candidate article, traverse typed edges: amended-by / repealed-by (is
this text current?), guided-by (pull implementing Thông t ư ), cites (one hop of
context).
04 Pairwise judgment
Frontier LLM classifies each (draft clause, retrieved clause) pair: contradicts /
duplicates-overlaps / compatible-related, with reasoning grounded in quoted
text.
05 Rules & report
Deterministic hierarchy logic (lex superior / posterior / specialis per Lu ậ t Ban hành
VBQPPL) ranks severity; composer emits the cited report for lawyer verification.

§  U P DAT E  A RC H I T E CT U R E
The knowledge graph stays current
New documents are published continuously; validity statuses flip; amendments
land. The graph is therefore built as an append-only, delta-driven system: every
refresh is a snapshot run whose cost is proportional to what changed, not to the
corpus.

The refresh job — scheduled (cron) and idempotent: re-running the same snapshot is a no-op.
Mechanisms
Ingest ledger + hashing. Each incoming document is classified against stored
(metadata_hash, content_hash)  as NEW / META_CHANGED /
CONTENT_CHANGED / UNCHANGED / MISSING. Only changed documents
flow through parse →  chunk →  embed.
Append-only versions, tombstones for deletion. Nothing is updated in place;
superseded rows get seen_to  stamped and is_current=false . History is
queryable; rollback is trivial.
Incremental propagation. When document X changes, the affected set is
computed by graph closure (X's articles plus neighbors via
amends/repeals/guides edges) and derived effective_status  is recomputed
for that subgraph only. Article-edge extraction re-runs only for changed
amending documents.
Transactional index sync Vector + full text indexes live in the same Postgres

Transactional index sync. Vector + full-text indexes live in the same Postgres
as the graph, so a delta commit updates graph and indexes atomically — no
drift between "what the graph knows" and "what search returns". Queries filter
on is_current .
Embedding model versioning. Every chunk records its embedding_model ;
upgrading the embedder becomes a tracked batch migration, not a flag-day
rebuild.
Edge provenance. Portal edges ( source='vbpl' ) and extracted edges
( source='extracted' , with model + confidence) are never merged silently;
refreshed portal data can correct extracted edges but not vice versa.
Report invalidation. report_citations  links past analyses to the article
versions they cited; when a version is superseded, affected reports are flagged
— enabling "a document cited in your report has changed" notices later.
Why not GraphRAG-style construction? LLM entity-graph extraction exists for
corpora that lack a graph. This corpus ships an authoritative, human-curated one.
The only construction performed is grounded article-level edge parsing from
explicit amendment statements — cheap, verifiable, and re-runnable per delta.

§  T H I N  S L I C E  &  R I S KS
Definition of done, and what could bite
MVP is done when: a lawyer pastes a draft provision into the web UI and receives,
within about a minute, a per-clause report over the sample sector — each finding
classified (conflict / overlap / related), severity-ranked by hierarchy, and cited to
exact Đ i ề u/Kho ả n with current-validity and amended-by flags — and the eval
harness reports retrieval recall@k and judgment precision/recall on the weak-
label set.
parsing  Vietnamese legal HTML is inconsistent across decades; the parser
needs a fallback path (flat article split) and a parse-quality metric from day
one.
false positives  Flagging conflicts against repealed or amended text destroys
trust instantly — validity and amendment flags are enforced in the retrieval
filter, not just displayed.
false negatives  The expensive error. Retrieval is tuned recall-first; the eval
gold set exists precisely to measure the miss rate before lawyers do.
eval validity  Weak labels from repeal/amend edges approximate conflict; a
small hand-checked set (and later, B ộ  T ư  pháp rà soát reports) calibrates
them.
